# 苹果快捷指令搭建说明

## 目标

快捷指令运行时弹出一个可多选列表。用户选择要同步的健康指标，也可以选择“位置信息”和“Wi-Fi 信息”。快捷指令只向局域网内 Home Assistant 的随机 webhook 地址发送 JSON，不经过任何外部服务器。

首次运行时，快捷指令会在第一步集中声明 13 类健康数据访问，iOS 随后显示统一的健康授权页；“位置”和“本地网络”权限会在选择对应项目时请求。这些系统权限必须由用户亲自确认，无法也不应绕过。

## 零、直接安装（推荐）

无需手工添加数百个动作：

1. 在 iPhone 上下载并打开 [Apple Health Bridge.shortcut](dist/Apple%20Health%20Bridge.shortcut)。
2. 点击“添加快捷指令”。
3. 导入问题出现时，粘贴 HA 集成通知中的完整 webhook 地址。
4. 运行快捷指令，在弹窗中多选本次需要同步的健康、位置和 Wi-Fi 数据。
5. 首次运行先在 iOS 的统一健康授权页确认所需类型，再按提示授予位置或本地网络权限；以后直接运行即可。

成品需要 iOS 18 或更高版本。它在运行时不会访问外部服务器，只会向导入时填写的 HA 局域网 webhook 发送数据。下文保留手工搭建步骤，供排错或自行修改时参考；可复现源码位于 [`src/apple-health-bridge.cherri`](src/apple-health-bridge.cherri)，构建后处理与签名脚本位于 [`tools`](tools)。

## 一、准备 webhook 地址

1. 在 Home Assistant 中添加“Apple Health Bridge”集成。
2. 输入设备名称，例如 `张三的 iPhone`。
3. HA 会弹出持久通知，复制其中的完整 webhook 地址。
4. 如果通知被关闭，可以在该设备页面按“显示快捷指令连接信息”按钮重新显示。

推荐使用 HA 的内部地址，例如：

```text
http://homeassistant.local:8123/api/webhook/一段很长的随机字符
```

不要分享这个地址，它等同于该设备的上传密码。HA 端还会拒绝来自公网的请求。

## 二、创建快捷指令骨架

在 iPhone 的“快捷指令”App 中新建快捷指令，命名为 `同步健康到 HA`，按顺序添加：

1. **列表**：每行填写一个选项：
   - 步数
   - 步行与跑步距离
   - 活动能量
   - 锻炼时间
   - 站立小时
   - 心率
   - 静息心率
   - 血氧
   - 呼吸频率
   - 睡眠时长
   - 体重
   - 体脂率
   - 爬楼层数
   - 位置信息
   - Wi-Fi 信息
2. **从列表中选取**：开启“选择多个”；提示填写 `选择本次要同步的数据`。
3. **字典**：创建空字典，重命名变量为 `HealthData`。
4. **字典**：添加 `version = 1`，重命名为 `Payload`。
5. **当前日期**。
6. **格式化日期**：格式选 `ISO 8601`。
7. **设定字典值**：在 `Payload` 中把键 `timestamp` 设为格式化后的日期。

## 三、处理健康指标

添加“对所选项目中的每一项重复”。在循环中按下表为每个健康选项建立一个“如果”分支。

每个分支的通用动作：

1. **查找健康样本**：选择对应健康类型。
2. 日累计指标过滤为“开始日期是今天”，排序可不设。
3. 最新值指标按“开始日期”降序排列，并限制为 `1` 个。
4. **获取健康样本的详细信息**：选择“值”。
5. 日累计指标使用**计算统计数据 → 总和**；最新值直接取第一项。
6. 需要时使用**转换测量单位**，确保数值与下表单位一致。
7. 建立字典 `{value: 数值, unit: 单位, name: 中文名称}`。
8. 使用**设定字典值**，把该字典写入 `HealthData` 的对应键。

| 弹窗名称 | JSON 键 | 取值方式 | 单位 |
|---|---|---|---|
| 步数 | `steps` | 今日总和 | `steps` |
| 步行与跑步距离 | `walking_running_distance` | 今日总和 | `km` |
| 活动能量 | `active_energy` | 今日总和 | `kcal` |
| 锻炼时间 | `exercise_minutes` | 今日总和 | `min` |
| 站立小时 | `stand_hours` | 今日总和 | `h` |
| 心率 | `heart_rate` | 最新值 | `bpm` |
| 静息心率 | `resting_heart_rate` | 最新值 | `bpm` |
| 血氧 | `blood_oxygen` | 最新值 | `%` |
| 呼吸频率 | `respiratory_rate` | 最新值 | `breaths/min` |
| 睡眠时长 | `sleep_duration` | 过去 24 小时总和 | `h` |
| 体重 | `weight` | 最新值 | `kg` |
| 体脂率 | `body_fat_percentage` | 最新值 | `%` |
| 爬楼层数 | `floors_climbed` | 今日总和 | `floors` |

循环结束后，如果 `HealthData` 有值，使用**设定字典值**把它写入 `Payload.health`。

说明：不同 iOS 版本对睡眠样本的返回形式略有不同。若“睡眠时长”得到的是睡眠区间列表，需要分别取得开始、结束时间，计算每段持续时间后求和，不能直接把“睡眠阶段”文本当作小时数。

## 四、处理位置

添加“如果所选项目包含 位置信息”：

1. **获取当前位置**。
2. 分别用**获取位置的详细信息**取得纬度、经度、高度和水平精度。
3. 建立字典：

```json
{
  "latitude": 31.2304,
  "longitude": 121.4737,
  "accuracy": 12,
  "altitude": 8,
  "timestamp": "ISO 8601 当前时间"
}
```

4. 使用**设定字典值**写入 `Payload.location`。

## 五、处理 Wi-Fi

添加“如果所选项目包含 Wi-Fi 信息”：

1. 添加多个**获取网络详细信息**动作，分别选择网络名称、BSSID、信道、Wi-Fi 标准和速率。
2. 建立字典，并使用下列固定键：

```json
{
  "ssid": "网络名称",
  "bssid": "BSSID",
  "channel": 149,
  "standard": "802.11ax",
  "rate": 1200
}
```

3. 使用**设定字典值**写入 `Payload.wifi`。

部分旧版 iOS 没有信道、标准或速率选项。这些字段可以直接省略，至少保留 `ssid`；系统无法取得 BSSID 时也应省略，不能上传空字符串。

## 六、发送到 HA

1. 添加 **URL**，填入 HA 通知中的完整 webhook 地址。
2. 添加 **获取 URL 内容**：
   - 方法：`POST`
   - 请求正文：`JSON`
   - JSON 内容：魔法变量 `Payload`
3. 从返回结果中取得 `ok`。
4. 如果为真，显示通知 `已同步到 Home Assistant`；否则显示返回的 `detail` 或 `error`。

HA 成功响应示例：

```json
{
  "ok": true,
  "received": {"health": 2, "location": true, "wifi": true},
  "new_entities": ["heart_rate", "steps"]
}
```

## 七、个人自动化（可选）

如果保留运行时多选弹窗，快捷指令必须等待用户选择，适合手动运行。若以后希望无人值守同步，请复制一份快捷指令、删掉弹窗并固定要同步的项目，然后在“自动化”中选择“Wi-Fi”或“特定时间”，启用“立即运行”。

位置和健康数据很敏感。建议只使用局域网地址，不要把 webhook 暴露到公网，也不要把 BSSID 上传到不受你控制的系统。
